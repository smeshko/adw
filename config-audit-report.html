YAML Mismatches — 3 issues
These parameters appear in generated YAML but don't match the Pydantic model, meaning they'd either be silently ignored or cause validation errors.
  • commands.test / commands.build — Generated YAML nests these under a commands: key. The model expects top-level test_command / build_command. If a user uncomments these, they will be silently ignored (Pydantic doesn't have a commands field).
  • webhook.enabled — Generated YAML shows # enabled: false under webhook but WebhookConfig has no enabled field. The webhook is active if providers have enabled: true.
Leftovers — 10 parameters defined but never used at runtime
These exist in Pydantic models (and some in generated YAML) but no runtime code actually reads them.
  • git.commit_template — create_commit() always uses DEFAULT_COMMIT_TEMPLATE
  • task_manager.pr_title_format — PR title formatting never implemented
  • task_manager.include_labels — Label context enrichment not implemented
  • task_manager.include_parent — Parent task context not implemented
  • security.blocked_env_files — Env file blocking not wired up (defaults are hardcoded)
  • worktree.preserve_on_failure — Explicitly deprecated; worktrees always preserved now
  • validate.review_prompt — Custom review prompt loading not implemented
  • validate.review_focus — Review focus areas not implemented
  • validate.test_timeout_seconds — Defined in model but never accessed during test execution
  • logging.redaction.* — Full model hierarchy exists but bootstrap never wires it through
